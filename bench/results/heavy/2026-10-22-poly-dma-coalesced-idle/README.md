# Повтор DMA-теста на свободном компьютере

2026-10-22, Windows, RTX 4090, 128 ГиБ RAM. Пользователь разрешил повтор и сообщил,
что не будет пользоваться компьютером до завершения. Одна загрузка, четыре запроса,
без автоматических повторов и без нового запуска контроля с отключённой правкой.
Процесс штатно завершился с кодом 0; диагностических coverage failures нет.

С предыдущим изменённым прогоном совпали SHA256 exe, публичного входа, начального
профиля, короткие входные токены и коммит `7a2cf777`. Включён
`--coalesce-expert-dma`. Параметры рабочего батника: context 131072, batch 4096,
read-chunk 32768, stage 2848 МиБ, reserve/margin по 256 МиБ, rows-vram,
compact-scratch/graphs, 64 swaps, адаптивный кеш. Начальное размещение прежнее:
10441 RAM-эксперт и 567 постоянных GPU-экспертов. Пересборки не было.

|---|---:|---:|---:|---:|
| A, 50000 / 256 | 532.6 | 635.2 | 16.28 | 16.83 |
| B, 50000 / 256, без парковки | 557.5 | 640.4 | 16.93 | 18.11 |
| Возврат A, read=1 / 32 | — | — | 17.21 | 20.26 |
| Короткий, 1000 / 128 | 99.9 | 106.1 | 16.80 | 18.46 |

Префилл A: 78.7096 с. Сырой prompt B: 79.3345 с, из них парковка 1.262606 с;
после исключения парковки 78.071894 с. Возврат: prompt 2.7784 с, парковка 1.243482 с,
resume=49999/read=1. Короткий prompt: 9.4234 с, включая 1.1704 мс парковки.
Префилл рассчитан как реально прочитанные токены / время без внешней парковки.
Decode использует engine decode_ms и 255/31/127 межтокенных интервалов.

Для ориентира старый контроль без правки, НЕ переснимавшийся сейчас: A 524.5/16.38,
B без парковки 520.5/17.45, короткий 65.3/15.56 ток/с (prefill/decode);
возврат 21.78 ток/с decode. Он снят в другое время и не является контролем
с гарантированно тем же фоном Windows.

## Что можно заключить

На том же exe длинный префилл получился быстрее предыдущего изменённого прогона
на 19.3% и 14.9% по ток/с. Генерация длинных ответов также выше на 3.4% и 7.0%.
Прежнее падение длинных ответов относительно старого контроля здесь не повторилось.
Это согласуется с существенным влиянием условий работы компьютера, но отдельно
эффект фоновой нагрузки и самой оптимизации такая серия не устанавливает.

Все ID сгенерированных токенов A, B и возврата совпали с предыдущим изменённым
прогоном. У A также совпали число CPU/GPU-экспертов (48993/20925), uploads=465 и
MTP 23/39: объём decode-работы по этим показателям одинаков. У B MTP изменился
20/30 -> 17/21, у возврата 15/16 -> 17/17. Эти ответы нельзя считать одинаковым
внутренним вычислительным расписанием только по совпадению выходных токенов.
Короткий ответ имеет другие ID; кеш, CPU share и speculative policy не замораживались.

GPU в начале decode возврата снова не сразу на рабочей частоте: выборки
1065 МГц / 5001 МГц памяти, затем 2430 / 10251. В предыдущем изменённом прогоне
было 600 -> 1350 -> 2430 МГц. Поэтому одну причину просадки короткого ответа
нельзя объявлять окончательно установленной. Его выборка всего 32 токена.

## Файлы

- `manifest.json`: точная команда и хеши.
- `combined/results.json`, `request-*.json`: результаты каждого запроса.
- `combined/engine.stderr`: исходная числовая диагностика своего синтетического теста.
- `combined/samples.jsonl`: телеметрия процесса и системы, включая частоты.
- `transfer-analysis.json`: 22125 записей полного расчёта.
- `summary.json`, `summarize.py`: сводка трёх сохранённых серий и воспроизводимый
  офлайн-расчёт; скрипт не запускает модель.

Предыдущие результаты сохранены. Другие процессы не останавливались; приватные
промпты и сессии не читались. Код и конфигурация в этой серии не менялись;
результаты и отчёт не коммитятся.
