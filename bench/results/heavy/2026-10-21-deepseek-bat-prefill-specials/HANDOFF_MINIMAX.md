# Передача Минимаксу: корректный DeepSeek prefill на параметрах батника

Пользователь остановил дальнейшие прогоны Codex из-за остатка лимита и попросил подготовить
всё для проверки Минимаксом. **Исправленные модельные прогоны ещё НЕ запускались.** Сборка не нужна.

## Что проверить

Сравнить DeepSeek V4 Flash Q3_K_M на одном текущем exe в трёх режимах:

1. `run-dsv4-q3_k_m.bat` / `strata-dsv4-q3_k_m.json`, исходный no-disk со staging-кешем.
2. То же + `--no-disk-expert-exchange`, максимум обменов по умолчанию 1.
3. То же без `--no-disk` — mmap. Числовые настройки не менять.

Для каждого два ПОЛНЫХ входа по 50000 токенов, ответ до 256 токенов. Вторая задача отличается
в начале сообщения и не должна восстанавливать первый контекст: требуются resume=0/read=50000.
Первая и повторная обработка mmap показываются отдельно. Не выдавать первое чтение файла за
прогретую вычислительную скорость. Холодное состояние кеша ОС специально не навязывается.

Параметры: context=131072, batch=4096, read-chunk=32768, stage=2848 МиБ, rows-vram,
compact-scratch, compact-graphs, reserve=256 МиБ, no-disk load-margin=256 МиБ, swaps=64.
Рабочий профиль из конфига скопирован непрозрачно в `initial-expert-profile.txt`; содержимое
личных разговоров, логов и промптов не читается. Каждый режим получает отдельную одинаковую
копию этого профиля и отдельный каталог сессий. Оригинальный профиль не изменять.

## Ошибки прошлых данных — обязательно учитывать

Старый runner вызывал `tok.encode(rendered)` без `parse_special=True`. Вместо DeepSeek User
128803 передавались обычные BPE `[30,28217,6756,28217,32,...]`. Также не подставлялся BOS
в шаблон, не применялась защита литеральных управляющих токенов и принудительно отключался
thinking. В новой серии используется серверный default thinking.

В первой проверке обмена DeepSeek входы были всего 2050/6150 токенов и пустой профиль. Это
не замер производительности на рабочем запуске. При batch=4096 вход 2050 проходит ветку
одного батча в `src/poly/engine.cpp` (условие `n_calls == 1` в Engine::read), а длинный —
послойное чтение нескольких батчей. Сравнивать их tok/s напрямую нельзя.

Поздняя диагностическая серия `../2026-10-21-deepseek-bat-prefill/` уже взяла правильные
числовые настройки и копии рабочего профиля, но ошибка управляющих токенов ещё оставалась.
Её результаты сохранены, а отчёт явно помечен невалидным для обычного чата. Там:

| Режим | Первый полный вход, ток/с | Второй, ток/с | Второй без парковки |
|---|---:|---:|---:|
| No-disk | 582.69 | 579.38 | 587.76 |
| Обмен | 591.50 | 586.90 | 593.20 |
| Mmap | 234.45 | 700.70 | 710.17 |

Это **диагностика неверно подготовленного потока**, не доказательство скорости обычных запросов.
В пяти из шести запросов немедленный EOS; только второй mmap дал 256 токенов. Автоматических
обменов в той серии не было. Не использовать её для сравнения decode или работы адаптации.

Та же ошибка подтверждена в старом GLM-входе: 2050 старых ID против 2032 при распознавании
контролов; начало `[32365,49544,33974,...]` против `[154822,154824,154826,...]`.
**Заявление Codex о +6% GLM для обычного чата отозвано**, старый отчёт помечен. Нужен отдельный
корректный GLM-бенчмарк позднее; не тратить на него время до завершения текущего DeepSeek.
Арифметические и GPU-тесты обмена весами от подготовки чат-промптов не зависят.

## Что уже подготовлено и проверено без GPU

- `public-inputs.json`: реальные публичные сообщения, их два потока ровно по 50000 ID,
  контрольные суммы исходных docs и конфигурации.
- `input-validation.json`: оба потока получены **реальным Service.encode_prompt**, включая
  BOS=0, User=128803, Assistant=128804, thinking-open=128821 и защиту литералов внутри текста.
  Кешированное кодирование сервера совпало с полным на обоих входах.
- `run.py` и `helpers/`: локальные копии всех вспомогательных измерителей; старые каталоги
  экспериментов для импорта больше не требуются. Зависимости — сам репозиторий и его .venv.
- `initial-expert-profile.txt`: фиксированный снимок статистики для одинакового старта.
- `handoff-manifest.json`: SHA256 exe, конфига, батника, профиля и файлов комплекта.

Затем серия (ориентировочно 15–25 минут, объявить запуск и ожидание в чате):

```powershell

```

Если пользователь ограничит проверку двумя режимами:

```powershell
.\.venv\Scripts\python.exe -u bench/results/2026-10-21-deepseek-bat-prefill-specials/run.py --run-prepared --modes bat-no-disk bat-mmap
```

Не выполнять `--prepare-only` повторно: подготовленные входы уже есть, запись файлов эксклюзивная.
Не запускать рядом второй движок; runner проверяет наличие strata-poly и откажется его трогать.
Ничего не убивать, не перезапускать и не удалять ради места. При ошибке завершить штатно,
сохранить данные и выяснить причину; при ответе короче 32 токенов серия сама прекращается после
сохранения. Прежде чем повторять неудачный прогон, получить явное разрешение по AGENTS.md.

## Что вывести пользователю

Для каждого полного входа: read/resume, время полного prompt, время от RESUME до финального PP
(без парковки), оба tok/s, TTFT, длину ответа/finish, decode tok/s, попадания GPU и draft-счётчики.
Показать скорость на границе 32768 и итог 50000 отдельно. Текст EOS/мало токенов не замалчивать.

Сравнивать **расход процесса и собственные выделения**, не свободную VRAM всего компьютера:
dense/experts/KV/staging/rows/other/total, RSS/private, GPU Local/NonLocal, число GPU-экспертов,
число CUDA-графов. NonLocal сам по себе не означает VRAM spill. Сохранять частоты GPU, CPU,
page faults, системные/процессные дисковые счётчики. Системные чтения не называть чтениями
исключительно движка, faults не называть исключительно дисковыми.

Отдельно подтвердить автоматические обмены во втором режиме, отсутствие ошибок/восстановлений,
стабильность арены и графов. Переносы проверялись раньше, но хеширование весов во время этой
скоростной серии не включать: оно существенно тормозит. Проверить все параметры command.json,
одинаковый SHA256 exe/начального профиля, исходный профиль/JSON/батник после тестов.

Время prompt включает парковку предыдущего разговора — не путать её с матричными вычислениями.
Поле `resume_to_last_pp_*` измеряет интервал по приходу строк протокола и должно обозначаться
именно так. Сохраняются stdout-протокол, stderr, samples.jsonl и отдельные request-файлы.

Не коммитить каждый отчёт: пользователь это прямо отклонил. Не менять движок/JSON/батник
на основании короткой серии. Для статистического ускорения нужны повторы, равные условия и
контроль дрейфа; эта серия прежде всего закрывает отсутствующий корректный DeepSeek mmap-prefill.
