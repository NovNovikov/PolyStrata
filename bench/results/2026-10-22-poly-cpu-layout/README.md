# CPU gate/up и down: проверка порядка чтения и размеров заданий

2026-10-22, Windows, i5-13600KF, 12 worker threads, MSVC, ggml AVX2/FMA/F16C.
GPU и полная модель не запускались. Исследуется вычисление экспертов на CPU,
а не уже объединённая H2D-передача gate/up.

## Стенд

Отдельный `poly_cpu_layout_probe`, исключённый из default build. Выбраны первые
четыре эксперта каждого из 43 слоёв настоящего DeepSeek GGUF: 1975779328 байт,
1.840 ГиБ. Файл модели закрывается перед проверками и измерениями.
Gate/up Q3_K, down MXFP4 в 34 слоях и Q3_K в девяти. Размеры 4096/2048.

Один процесс и один набор весов, без перезапусков. Восемь вариантов, пять
перемешанных раундов, rows=1/4, по восемь полных проходов на sample. В каждом
блоке есть stock в случайной позиции и завершающий stock. Итог — 90 samples.
Фоновые приложения не контролировались. Рабочий exe не пересобирался/не заменялся.

Перед измерениями 5504 проверки побитового совпадения полных выходных векторов
и однократного callback: rows=1/2/4/8, разное число экспертов по строкам,
переиспользование экспертов, SiLU/GELU, 1/12 потоков. Все прошли.
Timed calls не включают callback: это изолированный CPU-путь, не CPU/GPU overlap.

## Результат

Знак плюс означает сокращение времени против среднего двух stock того же раунда,
ниже медиана пяти таких сравнений. Это не прямое сравнение общих медиан.

| Вариант | rows=1 | rows=4 |
|---|---:|---:|
| Down: плитка одного эксперта целиком, 16 строк | +1.31% | -0.53% |
| Down: то же, 64 строки | +1.29% | -0.08% |
| Down: прежний обход, задание 64 строки | -2.63% | +0.07% |
| Gate/up: задание 16 строк | -0.99% | +0.74% |
| Gate/up: задание 64 строки | -5.26% | -1.55% |
| Сначала gate плитки, затем up, 32 строки | -1.62% | +0.19% |
| То же, 64 строки | -0.38% | -0.91% |

Лучший кандидат rows=1, down expert-major16, выигрывает 4/5 парных сравнений,
но медианный эффект только 1.31%, а на rows=4 выигрывает 1/5. Stock внутри
одного блока различается на 1.9–6.7% для rows=1 и 1.0–3.5% для rows=4.
Оснований объявлять такую правку устойчивым ускорением и включать её нет.

Stock rows=1: медиана 54.492 мс, диапазон 52.293–58.787 мс за 43 слоя;
gate/up 32.144 и down 19.787 мс (медианы фаз не обязаны суммироваться в общую).
Stock rows=4: 159.139 мс, диапазон 150.288–182.376 мс на четыре строки/43 слоя;
gate/up 90.928, down 56.170 мс. Значения rows=4 — время всей пачки, не одного токена.

Абсолютные 54.5 мс здесь нельзя выдавать за регрессию против старых 33.1 мс:
условия машины и диагностический executable отличаются, отдельного сравнения
старого production binary с этим стендом не было. Варианты сравнивались внутри
одной серии. Полное отсутствие маленького эффекта из-за шума также не доказано.

## Что установлено по исходникам

- В текущей сборке dot products реально с AVX2/FMA/F16C. Значение GGML_AVX2=OFF
  в общем cache не отражает принудительные flags выбранного ggml-cpu target.
- Изменение ISA на AVX-VNNI и числа worker threads уже исследовано в серии
  `2026-10-20-poly-cpu-bottleneck`; прежние отрицательные результаты не повторялись.
- Перестановки чтения и настройка размера заданий не дали подтверждённого выигрыша.
- В многотокенном вызове один ggml dot product с nrc=1 выполняется отдельно
  для каждого использования эксперта. Повторная распаковка тех же квантованных
  весов между строками видна по коду. Настоящее многострочное SIMD-ядро с
  переиспользованием распаковки — отдельный кандидат, здесь не реализован и
  не измерен. Он относится к shared-expert multi-row случаям, не обещает выигрыш
  scalar decode. Перепаковка всех весов в больший формат не предлагалась.

Новых оптимизаций в рабочем движке не включено. Код стенда защищён test-only
макросом и коммитится отдельно; результаты не коммитятся. Выполнена Windows CPU
сборка и CPU-проверки; HIP/SYCL и end-to-end генерация этой серией не проверялись.
