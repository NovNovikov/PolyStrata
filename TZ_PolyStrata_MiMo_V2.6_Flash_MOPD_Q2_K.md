# Техническое задание: поддержка MiMo-V2.6-Flash-MOPD Q2_K в PolyStrata

**Проект:** PolyStrata  
**Целевая ветка:** `merge/upstream-20261101`  
**Базовый commit:** `62fa6f64bd7883373d8dca0e822dd2bb93535482`  
**Основной движок:** `strata-poly`  
**Целевая архитектура GGUF:** `mimo2`  
**Дата:** 05.11.2026

## 1. Цель

Реализовать полноценную поддержку **текстового инференса MiMo-V2.6-Flash-MOPD** в квантовке **Q2_K от ggml-org** внутри существующего универсального движка `strata-poly`.

Поддержка должна включать:

- Корректную загрузку оригинальных GGUF без переквантования.
- Text prefill и autoregressive decode.
- Гибридный global/sliding-window attention.
- MoE с 256 экспертами и top-8 routing.
- CPU/GPU expert offload с разными типами квантования матриц.
- Полноценную интеграцию с `--no-disk`.
- Совместимость с resident placement, DMA staging и динамическим обменом экспертов.
- Работу через существующий сервер PolyStrata.

**Главная цель:** корректный и практически применимый запуск MOPD Q2_K на RTX 4090 24 ГБ + 128 ГБ RAM, без чтения модельных весов с SSD на критическом пути генерации в режиме `--no-disk`.

Реализация должна интегрироваться в существующий `Engine`, а не создавать новый независимый runtime.

**Ограничение текущего этапа:** не запускать llama.cpp, не организовывать сравнения и parity-тесты с llama.cpp, не требовать результатов его инференса или бенчмарков. Проверки осуществлять средствами PolyStrata, изолированными математическими эталонами и имеющимися unit-тестами. Сопоставление с llama.cpp будет отдельной задачей после завершения порта.

Шаблон SWA, per-layer KV heads, RoPE параметры и attention sinks считывать из метаданных и/или нужных тензоров, а не зашивать расположение слоёв в CUDA.

| Компонент | Ожидаемый dtype |
|---|---|
| Expert gate | `Q2_K` |
| Expert up | `Q2_K` |
| Expert down | `MXFP4` |
| Attention projections | `Q8_0` |

Размер основной Q2_K ориентировочно 117.7 GiB. Вместо жёстко зашитых констант использовать размеры из GGUF и арифметику GGML.

## 5. Этап A — GGUF и регистрация `mimo2`

Предполагаемые новые файлы:

- `src/poly/mimo2.hpp`
- `src/poly/mimo2.cpp`

Зарегистрировать `general.architecture == "mimo2"` в существующей фабрике архитектур.

Реализовать необходимые hooks `Engine`: geometry, layer loading, проходы выделения памяти и вычисления, декодирование и иные обязательные методы согласно текущему API.

Переиспользовать общую загрузку GGUF, dense-весов и `load_moe()`.

Проверить:

1. Два GGUF-шарда распознаются как единая модель.
2. Per-layer массивы считываются полностью (48 элементов).
3. Fused QKV определяются по реальным формам и верному порядку Q/K/V.
4. Ожидаемые размеры fused QKV: global `[4096, 13568]`, SWA `[4096, 14848]` (проверить ориентацию и представление осей конкретного GGUF).
5. Gate/up/down являются отдельными stacked tensors с независимыми dtype и stride.
6. Размеры, alignment, offsets, dtype и границы проверяются.
7. Несовместимость сопровождается содержательной диагностикой, а не UB или crash.
8. Никакая модель семейства RL не подставляется вместо MOPD.

**Приёмка этапа:** чтение metadata/tensor manifest MOPD Q2_K и проверки геометрии проходят без необходимости загружать все модельные веса.

## 6. Этап B — attention

### 6.1. Ассиметричные K/V

Реализовать attention с:

- `head_k = 192`;
- `head_v = 128`;
- `n_head = 64`;
- `n_kv = 4` / `8` по слоям.

В существующем `attend()` общий параметр размерности K/V; для MiMo требуется либо расширить интерфейс с сохранением совместимости существующих архитектур, либо добавить отдельное специализированное ядро.

**Не использовать постоянное нулевое дополнение V до 192**. Временный padding допускается только внутри изолированного теста как математическая проверка.

### 6.2. RoPE

Поддержать:

- NeoX RoPE;
- частичную ротацию первых 64 компонент;
- global base `10000000` и SWA base `10000`;
- правильные абсолютные позиции при циклическом KV.

### 6.3. Sliding-window attention

Поддержать:

- 9 global / 39 SWA layers;
- окно 128;
- sinks согласно модели;
- causal masking;
- кольцевой KV;
- продолжение prefill после заполненного контекста;
- переход через границу кольца;
- много-токенные окна проверки.

Размер ring storage выбирать исходя из требований реализации к prefill/verify и корректного доступа к предыдущим токенам, не слепо по `window=128`.

### 6.4. Attention value scale

Применять значение GGUF `0.707` в правильной точке графа согласно архитектуре MiMo, после attention output projection, перед сложением с residual.

Не заменять точную константу приблизительным `1/sqrt(2)`.

### 6.5. KV-cache

Поддержать:

- FP16 KV — первоначальный режим отладки;
- Q8_0 KV — целевой режим экономии памяти.

Учитывать разные K/V размеры в расчётах памяти. Расширение Q8_0 KV на `mimo2` производить только после проверки совместимости математических операций и CUDA-кернелов.

**Приёмка этапа:** собственные детерминированные тесты attention PolyStrata проходят на маленьких синтетических тензорах, включая global/SWA, FP16/Q8_0, RoPE, sinks, wraparound, контексты 127/128/129 и сравнение с независимой скалярной CPU-формулой attention. **Никаких прогонов llama.cpp.**

## 7. Этап C — MoE и смешанное квантование

### 7.1. Router

Реализовать routing MiMo:

1. Sigmoid raw router logits.
2. Добавление expert bias **для выбора**, не для взвешивания выходов.
3. Top-8 по biased scores.
4. Веса выбранных экспертов из unbiased probabilities.
5. Нормализация выбранных весов.
6. Применение expert scale из метаданных, если предусмотрено.

Использовать `Lfm2Moe::route()` как возможную основу после проверки точной формулы MiMo.

### 7.2. CPU experts

Поддержать сочетание gate/up Q2_K и down MXFP4 через корректные GGML vector-dot / CPU kernels. Проверить SIMD-пути без требования AVX-512.

### 7.3. GPU experts

Обеспечить независимую обработку `gu_type`, `u_type`, `d_type`, совместимость native MMVQ, grouped kernels и mixed CPU/GPU execution. Проверить код resident GPU admission, чтобы он не предполагал единый формат всех трёх матриц.

### 7.4. Prefill

Проверить MMQ и fallback-ядра Q2_K/MXFP4 на SM 8.9. Не переквантовывать GGUF и не декодировать всю модель в FP16 как постоянный обходной путь.

**Приёмка этапа:** unit tests на синтетических весах подтверждают routing IDs/weights, сравнение выходов CPU/GPU и отсутствие пропущенных экспертов. Для аппаратно доступной конфигурации выполняется короткий end-to-end прогон внутри PolyStrata.

## 8. Этап D — `--no-disk` (обязательный, приоритетный)

**Интеграция в существующую уникальную реализацию PolyStrata — центральное требование.**

Переиспользовать:

- `ResidentMemory` / блокировку RAM;
- `ResidentPlan`, `plan_resident()`;
- `load_resident_experts()`;
- `ResidentDma`;
- постоянное размещение GPU-экспертов;
- staging / DMA;
- `--no-disk-expert-exchange`;
- `--coalesce-expert-dma`.

### 8.1. Обязательные инварианты

1. Dense-веса размещаются в VRAM согласно существующей модели `Engine`.
2. CPU-эксперты размещаются в собственном физически резидентном RAM-буфере.
3. Постоянно GPU-резидентные эксперты не имеют полного дубликата в RAM.
4. Недостаточная физическая RAM или отказ lock приводит к явной ошибке, а не к тихому paging.
5. После загрузки GGUF payload закрывается через существующие пути `close_data()`.
6. На критическом пути генерации нет повторного чтения модельных весов с SSD.
7. Временный DMA staging не создаёт второго постоянного полного model-size RAM буфера.
8. Владение и lifetime экспертных слотов остаются корректными при CPU/GPU обработке.

**Запрещено** заменять это mmap, OS page cache, обычным CPU offload или скрытым дисковым резервом.

### 8.2. Планирование памяти

Учитывать **реальную** память:

- Dense и output в VRAM.
- Embeddings в RAM согласно текущему `--no-disk`.
- GPU KV и буферы attention.
- Scratch и графы.
- DMA/staging.
- VRAM reserve/margin.
- CPU и GPU expert residency.

Сначала резидентное размещение без exchange. Затем дополнительный прогон с exchange.

Выводить диагностические значения: эксперты по RAM/VRAM, объёмы памяти, margins, KV, staging, количество/размер переносов и закрытие модельных файлов.

### 8.3. Dynamic expert exchange

Проверить на mixed Q2_K/MXFP4:

- корректное заполнение слотов;
- byte-exact round trip экспертных данных;
- синхронизацию CPU/GPU readers;
- swap atomicity/ownership;
- правильный rollback при сбоях;
- совместимость с coalesced DMA.

**Приёмка этапа:** `--no-disk` способен загружать модель при достаточных ресурсах, корректно отказывать при нехватке, закрывать файлы и генерировать без повторного чтения GGUF. Использовать аудит инструментов PolyStrata и, при возможности, независимый мониторинг model-file I/O. Никаких запусков llama.cpp.

## 9. Этап E — внутренняя проверка корректности (без llama.cpp)

**Обязательное изменение относительно исходного плана:** весь внешний parity/benchmark контур с llama.cpp отложен. Не устанавливать llama.cpp, не собирать, не запускать, не создавать скрипты автоматического сравнения и не требовать его логов.

Проверки выполнять следующими способами:

1. **Unit tests на вручную заданных малых тензорах:** attention, rotary, causal/SWA mask, sinks, router, normalization, value scale.
2. **Изолированный скалярный CPU reference**, написанный в тестах на простой математике; сравнивать CUDA attention с этой формулой. Этот эталон не должен зависеть от испытуемых CUDA kernels.
3. **Согласованность путей самого PolyStrata:** CPU-only эксперты против GPU-экспертов для идентичных входов; resident path против соответствующего независящего от размещения вычисления.
4. **Эквивалентность режимов:** `--no-disk` с выключенным/включенным exchange при одинаковых весах и параметрах; Q8_0 KV относительно FP16 KV в документированных пределах ошибки.
5. **Проверки структурных инвариантов:** dtype, размерности, expert IDs, нормализация весов, границы и распределение памяти.
6. **Короткие end-to-end sanity runs внутри PolyStrata:** успешная генерация без NaN/Inf, неверных индексов, неверного состояния KV и нарушений синхронизации.

Для численных тестов фиксировать максимальную абсолютную и относительную ошибку, cosine similarity и другие применимые метрики. Допуски должны иметь объяснение из формата вычислений и квантования.

**Важно:** наличие осмысленного текста в PolyStrata — только sanity check; это не доказательство эквивалентности внешней реализации. Полную междвижковую parity-проверку оставить на следующий этап по отдельному запросу пользователя.

Выполнять проверки на длинах 127/128/129, 4095/4096 и более длинных контекстах по мере возможностей модели и железа; не превращать отсутствие полной модели в блокер для unit-тестов.

## 16. Критерии приёмки

- [ ] MOPD Q2_K корректно распознаётся как `mimo2`.
- [ ] Оригинальный двухшардовый GGUF загружается без переквантования.
- [ ] K=192 / V=128 обрабатываются без постоянного padding.
- [ ] Global/SWA, sinks, RoPE и attention value scale реализованы.
- [ ] Top-8 routing и нормализация проверены unit-тестами.
- [ ] Gate/up Q2_K и down MXFP4 поддерживаются на CPU/GPU.
- [ ] CPU/GPU/mixed режимы проходят внутренние тесты согласованности.
- [ ] Prefill/decode работают в PolyStrata.
- [ ] `--no-disk` сохраняет resident RAM/VRAM placement без дублирования GPU-экспертов в RAM.
- [ ] GGUF payload закрывается после загрузки в `--no-disk`.
- [ ] На критическом пути инференса `--no-disk` нет повторного чтения весов с SSD.
- [ ] Staging и optional expert exchange протестированы на mixed dtype.
- [ ] Регрессии для существующих архитектур не обнаружены в выполненных тестах.
- [ ] Реализованы диагностика, документация и воспроизводимые локальные проверки.
- [ ] **Не выполнялись прогоны, сравнения и бенчмарки llama.cpp.**

**Главный критерий:** рабочая MiMo-V2.6-Flash-MOPD Q2_K внутри существующего `strata-poly` с сохранением уникального `--no-disk` механизма. Внешняя проверка через llama.cpp намеренно отложена и не блокирует приёмку текущего этапа; ограничение достоверности выводов без внешнего референса обязательно указать в отчёте.
